# Testing Standards

## 목적

이 문서는 변경 유형별 최소 검증 기준과 증빙 규칙을 정의한다.

## 테스트 계층

- 정적 확인
  - 문법, import, 기본 포맷, 설정 파일 무결성
- 단위 테스트
  - 함수, 모듈, adapter, parser, policy 단위 검증
- 통합 테스트
  - 여러 서브시스템 연결, facade, workflow, hooks 검증
- 스모크 테스트
  - 대표 실행 경로가 최소 기능을 수행하는지 확인
- 수동 검증
  - 자동화가 어려운 상호작용, CLI, provider, 승인 흐름 검증

## 최소 기준

- 설계 변경이 있으면 최소한 관련 단위 테스트 또는 수동 검증 계획이 필요하다.
- 공개 인터페이스가 바뀌면 회귀 테스트 또는 호환성 검증이 필요하다.
- 버그 수정은 재현 케이스와 수정 후 검증 케이스가 모두 있어야 한다.

## 작업 문서 연계 규칙

- `implementation-tasks.md`에는 각 task의 검증 방법을 적는다.
- `verification-report.md`에는 실제 실행한 테스트만 기록한다.
- 실행하지 않은 테스트는 실행한 것처럼 쓰지 않는다.

## 증빙 규칙

- 자동 테스트는 실행 명령과 결과 요약을 기록한다.
- 수동 검증은 시나리오, 기대 결과, 실제 결과를 기록한다.
- 막힌 테스트는 원인과 차단 조건을 기록한다.

## 완료 기준

- 요구사항 또는 버그 명세의 수용 조건과 검증 결과가 연결되어야 한다.
- 남은 리스크가 있으면 종료 전에 명시한다.
