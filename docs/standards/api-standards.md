# API Standards

## 목적

이 문서는 `agent-factory` 내부 함수, 도구, adapter, facade, workflow 인터페이스의 공통 규칙을 정의한다.

## 기본 원칙

- 공개 계약은 명시적으로 문서화한다.
- 하위 호환성은 기본값으로 간주한다.
- 인터페이스 변경은 문서와 검증 전략 없이 수행하지 않는다.
- 반환값은 호출자가 실패 원인을 판단할 수 있을 정도로 구조화한다.

## 인터페이스 설계 원칙

- 이름은 역할이 드러나게 짓는다.
- 하나의 함수 또는 도구는 하나의 책임만 가진다.
- facade는 단순 진입점이어야 하며 구현 세부사항을 과도하게 노출하지 않는다.
- adapter는 원본 시스템의 특성을 흡수하되 상위 계층에 불필요한 복잡성을 올리지 않는다.

## 호환성 원칙

- 기존 공개 함수, 도구 이름, 파일 경로를 변경할 때는 명시적 마이그레이션 계획이 필요하다.
- 새 인터페이스를 추가할 때는 기존 호출 경로를 즉시 제거하지 않는다.
- deprecated 상태는 문서에 명시하고 제거 시점을 적는다.

## 요청과 응답 규칙

- 입력은 가능한 한 명시적 필드 이름을 사용한다.
- 출력은 성공과 실패를 구분할 수 있어야 한다.
- 실패 응답에는 최소한 원인 분류와 사람이 읽을 수 있는 설명이 포함되어야 한다.
- 구조화된 반환값을 우선하고, 자유 형식 문자열만으로 상태를 표현하지 않는다.

## 오류 처리 규칙

- 예상 가능한 실패는 반환값 또는 명시적 예외로 처리한다.
- 외부 의존성 실패는 retry 가능 여부를 문서에 적는다.
- partial success가 가능한 경우 그 상태를 구분해 기록한다.

## 문서 요구사항

- 인터페이스가 바뀌면 작업별 설계 문서에 영향 범위를 적는다.
- 설계 수준 변경이면 `docs/architecture.md`와 `docs/change_history.md`도 함께 갱신한다.
