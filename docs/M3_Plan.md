# [Agent Factory] M3 Plan: 차세대 범용 플랫폼 마스터플랜 (V3 Architecture)

본 문서는 보스(User)께서 제시하신 3개월 뒤의 초격차 무기(M3) 비전을 달성하기 위해, 현재 `Agent Factory`의 아키텍처에 이식되어야 할 두 가지 핵심 엔진에 대한 통합 명세서입니다.

---

## 🚀 파트 1: 초동적 지능형 라우터 (Super-Dynamic Intelligent Router)
> **비전**: 단순한 난이도(이분법) 판별을 넘어, 다차원적 지표를 기반으로 1밀리초 만에 최적의 갓성비 두뇌를 동적으로 갈아끼우는 극한의 효율 엔진

### 1-1. 다차원 메타데이터 기반 실시간 스케일링
작업 지시가 떨어지면 라우터가 다음 4가지 지표를 순간적으로 계산하여 투입 모델을 결정합니다.
*   **Complexity (복잡도)**: 수학적 논증인가(o-series), 세밀한 코딩인가(Sonnet), 방대한 리서치인가(Pro)?
*   **Budget (예산)**: 이 태스크 단위에 할당된 예산 규모 (1원 vs 100원).
*   **Latency (요구 속도)**: 실시간 생성형 UI 파이프라인(Flash/Haiku)인가, 백그라운드 심층 배치 작업(Opus/Pro)인가?
*   **Health (API 상태)**: 현재 벤더의 API 응답 지연율 및 429 Quota 상태 실시간 체크.

### 1-2. 페르소나(Agent)와 지능(Model)의 기계적 분리
*   **구조**: `[페르소나 껍데기(System Prompt)] + [동적 플러그인 두뇌(Model)]`
*   특정 에이전트에 특정 벤더 모델을 정적으로 하드코딩하지 않습니다. 상황(태스크 난이도)에 따라 동일한 에이전트 내에서 초경량 모델부터 최고 추론 모델까지 자유롭게 뇌가 교체(Hot-Swap)됩니다.

### 1-3. 다단계 폭포수(Cascade Failover) 롤백
*   수행 중인 최신 모델이 컨텍스트 초과나 API 장애로 뻗을 경우, 작업 중단을 방지하기 위해 인간(Boss)의 개입 없이 **유사 스펙의 타 벤더 모델로 0.1초 만에 인수인계(Hand-over)**하는 동적 롤백 우회로를 내장합니다.

## 🛡️ 파트 2: 고도화된 스웜 거버넌스 (Advanced Swarm Governance)
> **비전**: 에이전트들이 유기적으로 이벤트를 주고받는 자율망(Pub/Sub) 환경에서 발생할 수 있는 런어웨이(통제 불능)를 원천 차단하는 상용(Enterprise) 수준의 제어 장치

이 거버넌스는 마스터 에이전트가 모든 이벤트의 길목(Hub)을 통제하는 **[Hub-and-Spoke 방사형 아키텍처]** 위에서 동작합니다.

### 2-1. 이중 트랙 기획 맵핑 (Dual-Track Planning)
*   **Track A (운영 트랙)**: 코어 비즈니스 로직(DB, 인증 등)은 `승인된 Spec ID` 기반의 허가제(Allowlist) 이벤트만 수용.
*   **Track B (샌드박스 트랙)**: 혁신적 아이디어나 실험용 UI 이벤트는 격리 큐(Isolated Queue)에 발행을 허용하여 창의성을 제한하지 않되 메인망 오염을 방지.

### 2-2. 다층 심판관 게이트 (Multi-Tier Verifier)
단일 검증관의 오탐/누락을 막기 위한 3단계 허들.
1.  **정적 검사 (Linter/AST)**: 문법 및 시스템 보안 침해 여부 고속 검사.
2.  **시나리오 모의 테스트 (Sandbox Eval)**: 종속성 에러 및 정상 빌드 확인.
3.  **추론 기반 인간 대체 (Reasoning Judge)**: o-시리즈 등 최고 논리 모델이 사용자의 진정한 의도에 부합하는지 최종 판결.

### 2-3. 입체적 무한 루프 차단 (Advanced Loop Breaker)
*   **제어 속성**: 단순 핑퐁 횟수(Depth) 제한(AS-IS)에 더해 **TTL (실행 만료 시간 제한)**, **Budget 예산 소진 차단**, 그리고 의미 없는 재시도를 막기 위한 **동일 이벤트 해시값(Hash) 반복 차단 로직**을 탑재하여 런어웨이를 거의 완벽히 제어합니다.

### 2-4. 리스크 기반 동적 승인 (Risk-Based HITL)
*   **Low Risk (저위험)**: 단순 UI 변경, 유틸리티 수정 등은 자율 처리 후 감사 로그(Audit)만 남김.
*   **Medium Risk (중위험)**: 큐에 계류시키고 지연 시간(Timeout) 내 인간 승인이 없으면 스웜 다수결로 자동 반영.
*   **High Risk (고위험)**: DB 파괴, 결제 모듈, 외부 메일 등 치명적 이벤트는 인간 주체(또는 2인 체제)의 명시적 승인 전까지 무기한 홀드.

### 2-5. 필수 보안 3대 인프라 (Security Foundation)
*   **Capability Token**: 에이전트 생성 시 부여되는 고유 권한 토큰. 권한 범위를 벗어난 명령/이벤트는 시스템이 1밀리초 만에 레이어 단에서 폐기(Discard)함.
*   **Immutable Audit Trail**: 이벤트 버스를 지나는 모든 대화 기록, 판정 근거, 통신 데이터는 위변조 방지를 위해 Append-Only 방식으로 영구 저장망(추후 지식 그래프의 토대)에 적재됨.
*   **Kill Switch & Rollback**: 프로젝트/에이전트 단위 즉시 정지 권한 및 보상 트랜잭션을 통한 논리적 원클릭 상태 복원(Undo) 체계 완비.
