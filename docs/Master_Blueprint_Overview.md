# 🏭 Agent Factory - 마스터 블루프린트 오버뷰 (Master Blueprint Overview)

> **이 문서는 무엇인가요?**  
> `Agent Factory` 시스템을 처음 접근하는 사용자를 위해 구성된 직관적인 개념도입니다. 기존의 복잡한 구조도(Architecture)를 벗어나 이 제품이 **어떤 제품인지**, **어떤 기능들이 있는지**, **어떻게 동작하는지(상세 단계)** 를 명확하게 보여줍니다.

---

## 1. 제품 개요 (이 제품은 무엇인가?)

**Agent Factory**는 단순하게 텍스트를 생성하는 AI 툴이 아닙니다.  
**사용자의 프로젝트 환경과 도메인 지식을 흡수해, 필요한 "초개인화된 AI 에이전트 군단"을 스스로 조립하고 진화시키는 자율형 AI 제조 공장(Factory)** 입니다.

### 🌟 3대 제품 철학
1. **나만의 파트너 (Personalized Squads):** 각 에이전트가 진행 상황과 컨텍스트 로그를 학습해 세상에 하나뿐인 프로젝트 맞춤형 컨설턴트 및 개발자로 성장합니다.
2. **기획 우선 설계 (Planning-First):** AI가 무턱대고 코딩을 시작하지 않습니다. 철저히 기획, 설계(Plan) 후 승인된 청사진 위에서만 아키텍처 작업을 실시하여 부작용(Hallucination)을 막습니다.
3. **자율 스웜(Swarm) 협업:** PM, 설계자, 개발자 등 다양한 역할을 나누고 "상태 기반 보드(Stateful Board)"를 통해 릴레이(티키타카) 방식으로 작업을 수행합니다.

---

## 2. 주요 기능 및 역량 (무엇을 할 수 있는가?)

Agent Factory의 코어 아키텍처(M3)는 5가지의 강력한 기술 엔진을 탑재하고 있습니다.

### A. 실시간 포지(Forge) & 무중단 핫업그레이드
- 에이전트가 작업 중 "처리 도구(Skill)"가 부족하다면, 스스로 작업을 멈추고 팩토리에 **도구 제작을 지시**합니다.
- 리서치 엔진(Himari)이 문서를 탐색한 후, 새 파이썬 모듈을 생성 및 검증합니다. 기존 파이프라인 중단 없이 곧바로 강제 주입(Inject)시켜 불가능을 극복합니다.

### B. 동적 인텔리전스 라우팅 (Dynamic Router)
- 각 에이전트의 역할과 현재 태스크 복잡도, 예산(Token Budget), 속성을 계산해 런타임에 가장 최적화된 LLM(Claude, Gemini 등)을 매칭합니다. 인프라 오류 발생 시 0.1초 만에 다음 모델로 핫스왑 제어(Cascade Failover)를 수행하여 무중단 환경을 만듭니다.

### C. 5-Layer 강력한 보안 및 통제 (Governance)
- 단순 명령 실행 엔진을 넘어 폭주를 막는 **거버넌스 레이어**를 구성했습니다. 
- 1) 정적 AST 분석, 2) 샌드박스 파일/격리 엑세스, 3) rm/del 등 위험명령 차단, 4) 프로젝트 스펙에 어긋나는 행동 모니터링 관리, 5) 인간 검토(HITL Gate)로 시스템 붕괴를 원천 차단합니다.

### D. 다중 크로스 검증 (Cross Verification)
- 한 에이전트의 산출물은 반드시 타 모델/에이전트에 의해 다면 피어 리뷰(A → B → C)를 거칩니다. 오류 패턴 판정 시 "스킬(Skill) 진화" 전략으로 즉각 피드백을 전달하여 퀄리티를 폭증시킵니다.

### E. 상태 기반 메모리 허브 동기화
- 에피소드 단위와 시맨틱 단위, 그래프 메모리를 결합한 기억망를 동기화(Supabase DB 또는 Git 매니징)합니다. 회사 컴퓨터와 집 컴퓨터를 이동하면서도 같은 프로젝트 컨텍스트를 완벽히 유지하여 이어서 작업할 수 있습니다.

---

## 3. 파이프라인의 명시적 단계 플로우 (Workflow Stages)

Agent Factory의 업무 체계는 크게 기획(Phase 1), 실행(Phase 2), 진화 및 검증의 루프로 동작합니다.

### 📝 Phase 1: Planning (기획 및 전략 준비 단계)
본격적인 작업 돌입 전 시스템의 기반을 다지는 승인제 단계입니다.

1. **프로젝트 분석 및 워크보드 부트스트랩:**
   - 부트스트랩 에이전트(ProjectPlanningDirector 등)가 사용자의 요건을 분석하여 `프로젝트 브리프(brief)`와 `롤 배분(role_plan)`을 설정합니다.
2. **RAG 기반 문서 파싱 (Ingestion Pipeline):**
   - 사용자 지식 문서를 청킹하여 Dense+Sparse 하이브리드 검색 기반 `Document Index` 문맥 사전을 만듭니다.
3. **태스크 구조 분해 (Work Item Generation):**
   - 전체 작업을 쪼개 마크다운 기반의 Task Items로 분별하여 할당 보드를 준비합니다.
4. **인간 승인 게이트 (Approval Gate - HITL):**
   - **이 시점에서 진행이 멈춥니다!** 사용자가 `Phase 1` 기획을 검토하고 승인(Approve)을 누르기 전까지는 일체 위험 행동/코딩 모드(Execution)로 넘어갈 수 없습니다.

### 🚀 Phase 2: Execution (오케스트레이션 및 동사 실행 단계)
승인 후, 멀티 에이전트 "스웜"이 다이나믹 오케스트레이터의 통제하에 업무를 수행합니다.

1. **상태 보드 및 정책 체크인:**
   - 오케스트레이터가 예산 버짓(Run Budget)과 태스크 가용성을 지속 체크하며 준비된 이벤트망(Message Bus)을 개방합니다.
2. **태스크 디스패치 및 라우팅:**
   - `Lilith(통제 LLM)`가 큐에서 방해물(Blocker)을 확인하거나 빈 태스크를 확인하여 최적 모델과 스킬(최대 12개 선택)을 에이전트에게 장착시킵니다.
3. **에이전트 단일(혹은 병렬) 작업 수행:**
   - 에이전트별로 보안 샌드박스 내부에서 지정된 Task를 수행하며 Mailbox(이메일 비동기 방식)나 TCP 메시지로 동료 역할 에이전트와 티키타카를 주고받습니다. (ex. 개발자 ⇄ 검수자)

### ♻️ Phase 3: FSA (자가 검증 및 진화 루프)
각 작업의 산출물 품질을 끊임없이 올리는 피드백 루프입니다.

1. **다면 교차 검증 (CrossVerificationLoop):**
   - 결과물이 도출되면 병렬로 2개 이상의 CLI(오케스트레이터)가 순환 피어 리뷰를 실행, 최종 결과(verdict), 실패 항목(failure patterns) 등을 파악합니다.
2. **스킬 포지 및 자가 진화 (Skill Forge):**
   - 위에서 'Fail'이나 '지식 부족' 판정이 뜬다면 팩토리가 멈추지 않고, 스스로 리서치 모델을 띄워 빈틈을 보강할 **기능 파이썬 코드(Skill)**를 자체 생성하고 안전성을 AST 검사, 샌드박스로 증명합니다.
3. **무효화 및 재실행 (Hot-Upgrade Reload):**
   - 완성된 새 능력이 레지스트리에 저장되며 7단계에 걸친 캐시 무효화를 브로드캐스트합니다. 이후 첫 실행 파이프라인에서 실패했던 그 부분부터 개선된 역량으로 즉시 재시도하여 작업을 완료합니다.
4. **자동 문서화 동기화 (Auto Code-Review Doc):**
   - 완료 후 뒷단(Backgorund) 스레드를 통해 변경 사항을 추출하고 자동 리뷰 가이드를 남겨 지속가능한 시스템을 완성시킵니다.
