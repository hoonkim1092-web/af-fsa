# 패러다임 전환: Agent Factory vs Claude Code Skills 2.0 심층 비교 및 보완 전략

사용자님께서 제시해주신 **"문서에서 소프트웨어 모듈(앱)로의 진화"**라는 통찰은 현재 Agent Factory 시스템이 직면한 한계와 완벽히 일치하며, 앞으로 나아가야 할 방향성을 가장 정확하게 짚어주셨습니다. 

단순히 스킬을 '가진' 것을 넘어, 스킬을 어떻게 **'격리하고 제어할 것인가(컨텍스트 엔지니어링)'**의 관점에서 Agent Factory와 Claude Code Skills 2.0을 비교하고, 시스템을 어떻게 뜯어고쳐야 할지 명시적이고 상세하게 정리했습니다.

---

## 1. 핵심 차이점 비교 (Agent Factory vs Claude 2.0)

현재 Agent Factory는 **스킬 1.0 (자연어 매뉴얼 + 단순 파이썬 함수)** 수준에 머물러 있습니다. 이를 Claude 2.0의 관점에서 해부하면 다음과 같은 치명적 차이가 존재합니다.

| 구분 (기능) | Agent Factory (현재 스킬 1.0) | Claude Code Skills 2.0 (스킬 모듈/앱) | 문제점 및 차이점 |
| :--- | :--- | :--- | :--- |
| **정의 방식** | `.py` 파일 안의 단순 함수 단위 + YAML 배일에 이름만 나열 | 파일 상단의 **YAML Frontmatter**로 스킬의 메타데이터(설명, 훅, 에이전트 지정)를 독립적 앱처럼 정의 | Factory는 스킬이 '무엇'인지 메인 프롬프트에 구구절절 써야 해서 **토큰/컨텍스트를 심각하게 낭비**함. |
| **실행 환경** | 메인 에이전트의 단일 윈도우에서 모든 스킬을 순차적으로 실행 | **Context Fork(컨텍스트 포크)**를 통한 '격리 공간(Sandbox)' 실행 | Factory는 스킬 로그와 결과물이 메인 대화창에 섞여 환각(Hallucination)이 급증하고 맥락이 오염됨. |
| **개입 (Hook)** | 에이전트가 알아서 도구를 호출하고 결과를 판단 (개입 불가) | 5계층의 **독립적 훅(Hook)** 시스템 구조. 특정 분기에서만 필요한 '추가 지시' 강제 주입 | Factory는 매번 "코드 짤 때는 리뷰해!"라고 메인 프롬프트에 명시해야 하나, 2.0은 리뷰 훅에서 알아서 백그라운드로 처리함. |
| **품질 검증** | 하드코딩된 정적 에러 검증 (`StrategyEvaluator`) | **스킬 Evals (자동 품질 검증)**: AI가 테스트 스크립트를 짜고 정량적 통과 여부 측정 | Factory는 사용자가 스킬을 만들고 직접 돌려봐야만 그 스킬의 성공 여부를 알 수 있음 ("기분/감"에 의존). |
| **유지보수** | 코어 재시작 필요 | **스킬 크리에이터 + Hot Reload**: 스킬 수정 시 세션 재연결 없이 즉각 반영 | Factory는 스킬이나 프롬프트를 고치면 CLI/터미널 세션을 껐다 켜야 하는 생산성 병목 현상 발생. |

---

## 2. Agent Factory의 한계 및 보완해야 할 점

사용자님의 분석에 비추어 볼 때, Agent Factory가 코딩 에이전트로서 '압도적인 초격차'를 내기 위해 즉시 보완해야 할 점(Gaps)은 **컨텍스트 엔지니어링(Context Engineering)의 부재**입니다.

1. **메인 컨텍스트 윈도우의 오염 및 낭비**: 현재 Factory는 모든 스킬의 설명과 결과물이 메인 에이전트(`Deadbyte`, `Obanai` 등)의 뇌로 다이렉트로 들어갑니다. 이는 스타크래프트로 치면 본진에 모든 건물을 다 지어놔서 유닛이 엉키는 꼴입니다.
2. **소프트웨어 모듈(앱) 관점의 부재**: 스킬들이 독립적인 생명주기를 가진 앱이 아니라 단순한 스크립트로 동작하므로, 다른 프로젝트로 가져가거나 남이 만든 스킬을 신뢰하고 쓸 수 없습니다. `evals.yml` 같은 자체 보증 수표가 없습니다.
3. **핫 리로드 지연**: 스킬을 테스트하고 고치는 생애 주기(Life Cycle) 자체가 개발자에게 너무 불친절합니다.

## 3. 강력하게 적용했을 때의 효과 (The Impact)

이러한 "문서에서 소프트웨어로의 진화(2.0)"를 Agent Factory 코어에 성공적으로 정착시켰을 때 얻게 되는 폭발적인 효과는 다음과 같습니다.

* **극한의 컨텍스트 보존률 (컨텍스트 엔지니어링 완성)**: 메인 에이전트는 사용자의 '의도'와 '결정 사항'만 집중합니다. 무거운 자료 조사(`gap-detector` 등), 문법 검사, 터미널 실행 등은 **컨텍스트 포크**를 통해 백그라운드의 서브 에이전트가 격리된 공간에서 조용히 처리하고 '요약본(결과)'만 메인 뇌로 쏴줍니다. 환각이 0%에 수렴하게 됩니다.
* **무한 확장 가능한 생태계 (Evals + YAML Meta)**: 누구나 자신이 만든 스킬 블록 상단에 의존성, 훅, 버전 정보를 YAML로 적고, 이를 보증하는 Evals 테스트셋을 붙여 배포할 수 있습니다. 팩토리는 거대한 "에이전트 앱스토어" 구조를 갖추게 됩니다.
* **개발 생산성 10배 향상 (Hot Reload)**: 에이전트가 오류를 뱉으면 터미널을 끄지 않고, 스킬 스크립트만 고치면 바로 재시도하여(Hot Reload) 문제를 즉각 해결할 수 있습니다. 기존 1시간 걸리던 스킬 튜닝이 5분으로 단축됩니다.
* **"AI는 잡일을 하고 인간은 결정만 한다"의 실현**: 사용자는 메인 윈도우에서 "결제 모듈 리뷰해 줘"라고만 하면, 백그라운드 훅이 알아서 테스트 코드 스킬, 스타일 체커 스킬을 격리 로딩하여 실행한 뒤 승인 여부만 물어보게 됩니다.

## 4. 아키텍처 적용을 위한 명시적이고 상세한 "5단계 마스터 플랜"

위의 철학을 Agent Factory의 파이썬 기반 아키텍처에 구현(Implementation)하기 위한 구체적인 엔지니어링 단계입니다.

### [Step 1: 프론트 메타(YAML Frontmatter) 기반 시스템 개편]
* **작업 대상**: `core/skill_registry.py` 및 `skills/` 하위 파일 전체.
* **상세 작업**: 단순히 파이썬 데코레이터(`@skill_metadata`)를 넘어서, 폴더 구조를 **`skills/{skill_name}/`** 형태로 모듈화합니다.
* **형태**: 폴더 안에 `skill.py`, `meta.yml`, `eval.yml` 세트를 필수 구성 요소로 만듭니다. `meta.yml`에 이 스킬이 '어떤 서브 에이전트를 깨워서', '어느 훅(Hook)에 개입할지' 명시합니다. 이제 스킬은 하나하나의 미니 앱(App)이 됩니다.

### [Step 2: 컨텍스트 포크(Context Fork) 샌드박스 엔진 도입]
* **작업 대상**: `core/agent_runner.py`
* **상세 작업**: 메인 통신 채널(`LLM_Engine`)과 별개로, 서브스레드에서 동작하는 `ForkedLLMEngine`을 신설합니다.
* **동작 원리**: 스킬 발동 시, 메인 에이전트의 현재 컨텍스트를 복사(Fork)하여 별도의 임시 에이전트에게 넘깁니다. 임시 에이전트가 긴 터미널 출력을 해석하거나 검색 결과를 요약하여 처리한 뒤, 그 결과("검색 완료: 요약 내용")만을 메인 컨텍스트 모델에 리턴하여 뇌 용량을 아낍니다.

### [Step 3: 5계층 Hook 시스템 코어 배관 연결]
* **작업 대상**: `core/hooks/event_bus.py`
* **상세 작업**: 사용자 지시 시작 $\rightarrow$ 도구 선택 $\rightarrow$ 도구 실행(컨텍스트 포크) $\rightarrow$ 도구 검증(Eval) $\rightarrow$ 최종 답변이라는 5단계 라이프사이클 훅을 정의합니다.
* 특정 스킬 모듈의 `meta.yml`에서 `on_tool_execute: add_context("Security compliance strict rule applies")` 처럼 선언하면, 팩토리는 해당 훅 시발점에만 추가 지시를 밀어넣습니다.

### [Step 4: 스킬 Evals(자가 품질 검증) 에이전트 구축 및 통합]
* **작업 대상**: 신규 생성 `core/skill_evaluator.py`, 기존 `core/fsa_loop.py`
* **상세 작업**: 사용자가 스킬 개발을 마치면, 팩토리 내부의 `Evaluator Agent`가 `eval.yml`에 명시된 10개의 가상 상황을 백그라운드로 실행합니다.
* 성공, 실패, 오작동률(False Positive)의 스코어를 터미널에 출력합니다. 이 점수가 90점을 못 넘으면 애초에 `AgentManager`가 해당 스킬을 로드하지 않도록 밴(Ban) 처리하여 시스템 자정 능력을 확보합니다.

### [Step 5: 스킬 크리에이터 및 Hot Reload 파이프라인 완성]
* **작업 대상**: `agent_launcher.py`, 신규 `core/hot_reloader.py`
* **상세 작업**: Python `importlib.reload` 기능을 활용하여 `HotReloader` 감시(Watch) 스레드를 돌립니다.
* 에이전트와 대화 중(세션 유지 중) 사용자가 에디터에서 `skill.py`나 `meta.yml`을 수정하고 저장하면, 이를 즉시 감지하여 메모리에 올라간 모듈을 바꿔치기합니다. (에이전트가 "앗, 규칙이 바뀌었네요! 다시 시도하겠습니다." 하고 고쳐진 스킬을 즉각 활용하게 됩니다.)
