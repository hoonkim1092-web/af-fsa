# [Agent Factory] Skill Creator (품질 검증 자동화) 도입 및 이식 방안

## 1. 개요 (Background)
본 문서는 기존의 '감(느낌)'에 의존하던 에이전트/스킬 설계를 **'데이터 기반의 객관적 품질 검증 자동화(Automated QC)'**로 전환하기 위한 `Skill Creator` 방법론의 Agent Factory 이식 방안을 정의합니다.

기존 프롬프트 엔지니어링의 한계를 극복하고 모델 업데이트 시 발생하는 간섭(Interference) 현상을 방지하기 위해 도입됩니다.

## 2. 스킬 정의 및 분류 체계 재정립
Agent Factory 내 에이전트가 사용하는 도구(Skill)를 목적에 따라 명확히 이분화합니다.

*   **능력 향상 스킬 (Capability Enhancement):** 특정 프레임워크 템플릿 작성, 복잡한 로직 처리 등 현재 AI 모델의 한계를 일시적으로 보완하는 도구. 향후 기본 모델 업그레이드 시 검증을 거쳐 **'자연 은퇴(Archived)'** 처리될 수 있습니다.
*   **규칙 강제 스킬 (Encoding Preferences):** `GEMINI.md` 헌법 준수, 특정 사내 보안 규정 검토, 정해진 배포 워크플로우 강제 등 타협할 수 없는 절차적 도구. 모델의 업그레이드와 무관하게 영구적으로 유지됩니다.

## 3. 적용 전/후 (As-Is vs To-Be) 비교

| 구분 | As-Is (과거 방식) | To-Be (Skill Creator 도입 후) |
| :--- | :--- | :--- |
| **제작 및 검증** | PD(Lilith)나 사용자가 프롬프트를 작성하고, 몇 번의 샘플 테스트 후 합격/불합격을 체감으로 결정. | 팩토리가 자체적으로 20~30개의 테스트 셋을 만들고, 6개의 에이전트를 병렬로 띄워 블라인드 A/B 테스트를 통해 **승률(수치)**로 증명. |
| **호출(Trigger) 안정성** | 매니저 AI가 스킬 설명(Description)을 읽고 스스로 판단. 설명이 모호하면 스킬을 쓰지 않고 임의로 처리하다 실패함. | 훈련(60)/테스트(40) 분할 가상 쿼리 테스트를 통해, 에이전트가 **정확한 타이밍에 스킬을 꺼내들 때까지** 스킬 설명글을 최대 5번 자동 리팩토링. |
| **모델 기능 간섭 대응** | 새 모델 업데이트 시, 과거 임시방편으로 만든 능숙도 보완 스킬이 오히려 새 모델의 네이티브 능력을 제한하는 현상 발생. | 신규 모델(예: Claude Opus 5) 도입 시, 모든 '능력 향상 스킬'에 대해 재벤치마크 실행. 기본 모델이 스킬을 이기면 스킬을 자동 보관(Archived) 처리. |
| **피드백 및 유지보수** | 에러 발생 시 사용자가 직접 원인을 파악하여 프롬프트 레벨에서 수정을 지시해야 함. | `feedback.json` 등 규격화된 블라인드 채점표를 팩토리에 입력하면, 성공률 하락 원인을 자동 분석해 프롬프트를 리팩토링. |

## 4. 파이프라인 적용 단계 (Explicit Implementation Steps)

Agent Factory의 코어 엔진에 탑재될 **5단계 QC 파이프라인**입니다. 이 파이프라인을 통해 어떤 프로젝트를 조립하더라도 수치로 성능이 증명된 에이전트 군단을 무한히 찍어낼 수 있습니다.

### Phase 1: 자동화된 TDD 기반 스킬 포지(Forge) 가동
1. 신규 스킬/도구 제작 지시가 하달됩니다.
2. 스킬의 코드를 작성하기 전에, "이 스킬이 완성되었다고 판단할 수 있는 **기대 결과물 20개(정답지)**"와 테스트 케이스를 시스템이 먼저 자동 생성합니다. (기획 우위/Planning-First 원칙 적용)

### Phase 2: 블라인드 아레나(The Arena) 구성 및 실행
1. 두 개의 독립된 샌드박스 환경을 병렬로 생성합니다.
   - **Group A (Control):** 해당 스킬이 장착된 에이전트 3기
   - **Group B (Experimental):** 해당 스킬 없이 기본 지능만 가진 에이전트 3기
2. Phase 1에서 만든 테스트 쿼리를 동시에 실행시키고, 도출된 총 6개의 결과물을 식별자 없이 믹스(Mix)합니다.

### Phase 3: 하이브리드 지능 기반 이원화 평가
1. **능력 평가 (Qualitative):** 결과물의 퀄리티, 코드의 창의성, 논리의 유려함 등은 `Claude` 계열 아키텍트 엔진이 정성적으로 평가합니다.
2. **절차적 평가 (Procedural):** "특정 예외 처리 코드가 들어갔는가?", "금액 조건에 따라 정확한 분기를 탔는가?" 등의 엄격한 룰 검증은 `Gemini` 계열 엔진이 정량 평가(Pass/Fail)합니다.
3. 스킬을 사용한 Group A의 퍼포먼스 향상 수치가 기준치에 미달할 경우, 해당 스킬 구조를 폐기하거나 재설계합니다.

### Phase 4: 머신러닝 최적화 루프 (라우터 튜닝)
에이전트가 도구를 적절히 호출(Trigger)하는지 검증하고 최적화하는 단계입니다.
1. 도구를 **호출해야만 하는 상황 12개**(60%), **호출하면 안 되는 상황 8개**(40%) 분량의 텍스트 쿼리를 자동 생성합니다.
2. AI 매니저(라우터)에게 이 20개의 쿼리를 던져, 스킬 트리거 여부만 집중적으로 테스트합니다.
3. 오작동(False Positive / False Negative) 시, 팩토리는 스킬의 `Description(설명글)`을 더 명확하게 스스로 수정하여 다시 테스트합니다. (100% 성공할 때까지 최대 5 Iteration 한도 내 반복)

### Phase 5: 자가 진화 및 생애 주기 자동 관리 (Retirement Protocol)
1. 시스템 레벨에서 신규 AI API 적용 및 버전 업데이트(예: Claude 3.5 -> 3.7)가 발생하면, 트리거 이벤트를 수신합니다.
2. 팩토리는 백그라운드에서 전체 '능력 향상 스킬'을 대상으로 Phase 2 아레나 벤치마크를 재실행합니다.
3. **은퇴 프로토콜:** 신형 AI의 맨몸 성능(Group B)이 과거 작성된 스킬 장착 성능(Group A)을 넘어서면, 팩토리는 해당 스킬을 '자연 은퇴(Archived)' 처리하고 시스템을 가볍게 최적화합니다.
