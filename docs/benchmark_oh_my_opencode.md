## 2. Agent Factory 벤치마킹 🚀 3대 추천 스펙

우리가 2주 안에 즉시 벤치마킹해서 가져와야 할 기능 3가지야. 

### ① Todo Continuation Enforcer (강제 완수 루프)
- **왜 필요한가?** 고스트-파일럿이 병렬로 돌 때 가끔 에이전트들이 "이 부분 로직은 어떻게 짤까요?" 하고 사용자 입력을 기다리다 멈추는 경우가 발생할 수 있어.
- **도입 방안:** 에이전트 시스템 프롬프트나 팩토리 매니저 런타임에 **"사용자 개입 요청 절대 금지. 스스로 최선의 결정을 내리고 끝까지 코드를 작성하라"**라는 Enforcer 프롬프트 체인을 강제로 끼워넣어야 해.

### ② Dynamic Context Compaction (동적 컨텍스트 압축/정리)
- **왜 필요한가?** 100만 토큰 모델(gemini-3.1-pro 등)을 쓴다 해도, 로그가 길어지면 요점을 까먹거나 돈(비용)이 줄줄 샘.
- **도입 방안:** 
  1. **터널링 로그 압축:** 터미널 명령어나 `grep` 결과가 1000줄이 나오면, `head`/`tail` 혹은 초경량 모델을 태워서 핵심 20줄로 요약(Truncation)한 뒤 메인 프롬프트에 넘기는 **중간 필터 망** 구축.
  2. **오래된 대화 가지치기:** 컨텍스트가 일정 이상 쌓이면 요약본으로 대체하는 로직 추가.

### ③ 트리 구조별 규칙 자동 주입 (Directory Rules Injector)
- **왜 필요한가?** 지금은 `policy.yaml` 하나로 다 때우는데, 프론트엔드(`src/components`)와 백엔드(`src/api`)가 작업 룰이 다를 수 있어.
- **도입 방안:** 파일을 읽거나 수정할 때, 해당 폴더에 `.factory_rules` 같은 파일이 있다면 런타임에 자동으로 불러와서 에이전트 지시문에 밀어넣어주는 로직 추가. (마치 깃허브 액션처럼)

## 3. 심화 확장 기능 (Extra Tools) 벤치마킹 타당성 검토

보스가 추가로 제안한 oh-my-opencode의 심화 기능 및 도구들에 대한 타당성 검토 결과야. 

### 1) LSP Integration & AST-Grep 🟢 **[즉시 도입 확정]**
- **검토:** 기존에 우리가 쓰던 단순 `grep`이나 `cat`보다 훨씬 똑똑하고 안전함. 
- **시사점:** 개발 IDE 수준의 네비게이션(`lsp_goto_definition`, `lsp_find_references`)은 에이전트의 코드 이해도를 수직 상승시킴. 특히 AST-Grep은 코드를 텍스트가 아닌 '문법 구조'로 읽기 때문에, 리팩토링 중 사고칠 확률을 획기적으로 낮춰줌. **보스의 지시에 따라 이번 스프린트(Phase 5) 즉시 도입.**

### 2) Session History & Dynamic Codebase 🟡 **[선택 보류]**
- **검토:** 세션 히스토리와 실 실시간 파일 변경 모니터링은 좋으나, 우리 Agent Factory는 1회성 `고스트-파일럿` (단일 스크립트 실행 후 종료) 구조를 지향함. 
- **시사점:** 너무 무기한으로 데몬을 띄워두는 건 우리의 "Zero-Fat" 철학을 해칠 수 있으니, 당장보다는 추후 장기 체류형 에이전트 개발 시 도입 검토.

### 3) 큐레이팅된 MCP 서버 (Exa, Context7, Grep.app) 🟢 **[즉시 도입 확정]**
- **검토:** 웹 서칭, 공식 문서 파싱, 깃허브 검색을 전문 Tool로 빼두는 구조. 
- **시사점:** MCP(Model Context Protocol) 아키텍처를 도입하면 이 서버들을 거저 주워 먹을 수 있음. 파이썬 기반의 MCP 브릿지를 구축하여 Exa(초정밀 검색) 등의 능력을 수혈함. **보스의 지시에 따라 이번 스프린트(Phase 5) 즉시 도입.**

### 4) Multi-Account Load Balancing (Antigravity auth) 🟢 **[Phase 4 기적용]**
- **검토:** 무료 티어 API의 분당 제한(Rate Limit)을 우회하기 위해 계정 n개를 라운드 로빈 시키는 아이디어. 
- **시사점:** 이건 진짜 영악하고 실용적인 방식임. `model_utils.py`에 Google 계정을 1개가 아닌 여러 개(예: `GOOGLE_API_KEY_1`, `GOOGLE_API_KEY_2`) 등록해놓고, `429 Too Many Requests` 에러가 뜰 때마다 다음 키로 갈아타는 **오토-스위칭 로직**을 달아두면 팩토리 가동 비용을 엄청나게 절감할 수 있음.

## 4. 최종 확정된 신규 마일스톤 (Phase 4)

보스의 지시를 수용하여, 다음 5가지를 우리 시스템에 즉각 이식하기로 결정함:
1. **역할 명시적 호출 (`@oracle` 등)**: 사용자가 `@` 멘션으로 특정 엔진/페르소나를 콕 집어 호출할 수 있는 기능. 없으면 기존처럼 Autobahn 자동 맵핑 유지.
2. **동적 컨텍스트 압축망**: 도구의 출력 길이를 자르고(Truncation), 오래된 대화는 압축하는 지능형 메모리 관리 로직 구현.
3. **디렉토리별 규칙 자동 주입**: 특정 폴더 접근 시 `.factory_rules` 등을 런타임에 쏵 읽어와서 에이전트에게 밀어넣어 주는 기능 구현.
4. **Todo Continuation Enforcer**: "계속할까요?" 묻는 걸 원천 차단하고 끝까지 시스템이 자율 완수하도록 강제하는 UX. 단, 비개발자를 위해 난해한 CLI 플래그가 아닌 위저드 템플릿 폼에서 직관적인 Y/N 옵션으로 제어하도록 설계.
5. **API Key 라운드 로빈 (로드밸런싱)**: `model_utils.py`에 다중 API 키 배열을 등록하여 Rate Limit 한계를 돌파하는 비용 최적화 로직 추가.
