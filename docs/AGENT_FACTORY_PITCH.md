# Logi-Mind Agent Factory: 자가 진화형 멀티 에이전트 오케스트레이션 플랫폼
> **대상 독자:** 투자사(VC), CTO, 기술 리더십
> **현재 상태:** MVP 안정화 단계 (Phase 4)
> **핵심 가치 제안:** 코드를 실행하는 것에 그치지 않고, 시스템이 **스스로 필요한 역량을 코딩하고, 검증하며, 통제하는** 실시간 멀티 에이전트 합의 플랫폼.

## 1. 요약 (Executive Summary)
기존 LLM 에이전트들은 구조적 한계에 부딪힙니다. 자신이 가지고 있지 않은 도구(Tool)나 API 연동이 필요한 태스크를 만나면 멈춰버리기 때문입니다. 전통적인 방식에서는 엔지니어가 직접 개입해 새로운 파이썬 코드를 짜고, 테스트하고, 배포해야만 에이전트가 다시 작동할 수 있었습니다.

**Logi-Mind Agent Factory**는 이 병목 현상을 근본적으로 해결했습니다. 우리의 팩토리는 PM, 설계자, 디자이너, 개발자, 리서처 등 전문화된 AI 워커들이 모인 자율적인 "스웜(Swarm)"입니다. 이들은 **상태 기반 프로젝트 보드 (Stateful Project Board)** 를 통해 "티키타카(Tiki-Taka)" 방식으로 협업합니다.
만약 스웜 파이프라인 진행 중 필요한 역량(도구)이 부족하다면, 시스템은 엔지니어를 기다리지 않습니다. 스스로 프로세스를 멈추고, 도메인 지식을 바탕으로 문서를 리서치한 뒤, 단절을 메울 안전한 파이썬 모듈(Skill)을 실시간으로 **생성 및 검증(Forge)** 합니다. 이후 변경 불가능한 레지스트리에 이를 등록하고, 에이전트에게 **강제 핫-업그레이드(Hot-Upgrade)** 를 적용시켜 곧바로 작업을 재개합니다.

**우리는 단순한 AI 툴을 만드는 것이 아닙니다; 우리는 AI 툴을 스스로 제조하는 자율형 공장(Factory)을 만들고 있습니다.**

## 2. 3대 핵심 아키텍처 (Core Architectural Pillars)

Agent Factory는 업계의 3대 치명적 난제인 **에이전트 환각(Hallucination), 코드 쓰레기장화(Garbage/Duplication), 폭주(Runaway Execution Risk)** 를 원천 차단하도록 설계되었습니다.

### A) 스웜 카운실 (Orchestration Layer)
시스템의 두뇌인 `project_orchestrator.py` 입니다. 거대한 단일 LLM이 모든 것을 처리하려 하는 대신, 작업을 분리하여 "티키타카" 위원회가 검증합니다:
- **프로젝트 보드:** 진행 상황, 히스토리, 현재의 블로커(장애물)를 추적하는 중앙 집중식 JSON 상태 머신입니다.
- **역할 전문화:** 한 에이전트의 산출물은 반드시 파이프라인의 다음 에이전트에게 비판 및 검증을 받습니다.
- **릴리스(Lilith) 방어 로직:** 내장된 "레드팀(Red Team)" PM 에이전트인 Lilith가 시스템의 회사 사내 정책(`policies.yaml`) 위반 여부를 끊임없이 감시합니다. 다른 에이전트가 비효율적이거나 위험한 로직을 제안하면, Lilith가 즉시 기각(Reject)하고 설계를 반려합니다.

### B) 포지 & 지식 엔진 (Generative Layer)
Lilith가 에이전트의 역량 결핍을 인지하면, 팩토리는 "포지(Forge)" 시스템을 가동합니다:
- **히마리 리서치 엔진 (`core/research_engine.py`)**: 코드를 작성하기 전에, 시스템은 방대한 사내 도메인 문서가 담긴 중앙화된 NotebookLM(리버스 엔지니어링된 API 활용)에 질의를 던집니다. 이를 통해 생성되는 코드가 LLM의 허상이 아닌, 전문가 수준의 컨텍스트에 기반하도록 강제합니다.
- **팩토리 매니저 (`factory_manager.py`)**: 리서치 결과를 바탕으로 공백을 메울 실제 파이썬 코드(Skill)를 동적으로 작성합니다.

### C) 에이전트 거버넌스 및 런타임 제어 (Security Layer)
자율 코딩 기능의 가장 큰 리스크는 똑같은 기능의 코드를 중복해서 무한 생성하는 "코드 무덤" 현상과, 파괴적인 코드가 브레이크 없이 실행되는 "폭주" 현상입니다. 우리의 Phase 3/4 아키텍처는 이를 완벽히 통제합니다:
- **시맨틱 스킬 레지스트리 (`core/skill_registry.py`)**: 생성된 모든 신규 코드는 LLM 임베딩을 통해 기존 역량 풀(Pool)과 의미론적 유사도(Semantic Similarity) 비교를 거칩니다. 만약 80% 이상의 목적이 겹치는 스킬이 이미 존재한다면 생성을 차단하고 기존 코드를 재사용합니다. (중복 방지)
- **보안 실행기 (`core/executor.py`)**: 시스템에 깊숙이 개입하는 실행은 반드시 샌드박스 래퍼를 통과해야 합니다. 엄격한 타임아웃, 메모리/호출 격리, 관측 가능한 로깅을 통해 에이전트가 무한 루프에 빠지거나 위험한 명령을 실행하는 것을 기계적으로 차단합니다.
- **자동 문서화 훅 (Auto-Docs)**: 스킬이 갱신될 때마다 레지스트리의 최신 상태를 `skill_docs.md` 파일로 자동 추출하여 시스템의 능력을 인간(CTO/엔지니어)에게 실시간으로 투명하게 공개합니다.

## 3. "핫업그레이드" 매직 (실제 사용 시나리오)

**시나리오:** 사용자가 프론트엔드 에이전트에게 "새로운 비정형 PDF 포맷에서 벤더 견적서를 추출해줘" 라고 요청함.
1. **Tech Lead 에이전트**가 작업에 돌입했으나 PDF 파싱 도구가 없음을 깨닫고 실패 리포트를 작성함.
2. **PM 에이전트 (Lilith)** 가 이를 가로채 "우리 스 Warm에 PDF 추출 스킬이 누락되었다"고 판단, 팩토리에 제작을 명령함.
3. **리서치 에이전트 (Himari)** 가 NotebookLM에 접속해 최신 OCR 및 PDF 데이터 추출 아키텍처를 조사함.
4. **Factory Manager**가 리서치 데이터를 기반으로 완벽한 `pdf_extractor_v2.py` 를 코딩함.
5. **Skill Registry**가 이 코드가 중복인지 의미론적으로 판별하고, 완전한 신규 스킬임을 인증함.
6. 스킬이 레지스트리에 등록됨과 동시에 Tech Lead 에이전트의 워크스페이스에 강제 주입(Inject)됨.
7. 파이프라인이 즉각적으로 멈춘 지점부터 작업을 재개하여 PDF 파싱을 완수함.

**결과: 사람(엔지니어)의 개입 없이, 시스템 중단(Downtime) 없이, 단 몇 분 만에 에이전트가 스스로 한계를 극복했습니다.**

## 4. 경쟁 우위 및 투자 효용성 (ROI)

| 지표 (Metric) | 전통적인 LLM 에이전트 | Logi-Mind Agent Factory |
| :--- | :--- | :--- |
| **역량 확장성** | 사람 엔지니어가 직접 툴 코딩 필요 | **자율 생산** (에이전트가 스스로 툴 코딩) |
| **실행 안전성** | 맹목적인 Subprocess 코드 실행 | **보안 엑스큐터**를 통한 메모리/타임아웃 락 |
| **코드 퀄리티** | 낮음 (비슷한 코드가 계속 생성되어 쌓임) | **최상** (시맨틱 레지스트리가 중복 생산 원천 차단) |
| **도메인 특화** | 일반적인 LLM 지식에 의존 | **NotebookLM (`Himari`) 연동**을 통한 심층 RAG 적용 |

**For Investors (투자사 대상):** 이 플랫폼은 누구도 쉽게 넘볼 수 없는 기술적 "해자(Moat)"입니다. 우리는 개발자가 AI 워크플로우를 따라다니며 뒤치다꺼리해야 하는 병목을 뚫어냈습니다. 성장은 개발팀의 머릿수(Headcount)가 아닌 컴퓨팅 자원(Compute)에 비례하여 기하급수적으로 확장 가능합니다.

**For CTOs (기술 리더 대상):** 완벽한 거버넌스를 보장합니다. 시스템의 심장인 `policies.yaml`과 자동 생성된 `skill_registry`는 당신의 통제 하에 있습니다. 개발 속도를 전혀 희생하지 않으면서도 AI가 어떤 위험한 코드를 실행할지, 어떤 능력을 가지게 될지 100% 모니터링하고 제어할 수 있습니다.

## 5. 다음 전략적 마일스톤 (Next Milestones)
- **Multi-Cloud Sandboxing:** 로컬 파이썬 `subprocess` 레벨의 제한을 넘어, Docker나 WASM 기반의 클라우드 샌드박스로 격리 레이어를 올려 극강의 보안 실행 달성.
- **Agent Mesh Networking:** 로컬의 팩토리 엔진을 Supabase 등 리모트 데이터 웨어하우스와 연결, 제로 트러스트(Zero-trust) 기반으로 에이전트 간 데이터 교환 파이프라인 구축.
- **UI Dashboard:** 현재 터미널 로그로 쏟아지는 실시간 프로젝트 보드 협업 상황을, 인간 관리자가 한눈에 볼 수 있는 세련된 Next.js 기반 대시보드로 이전 (Visual 오버사이트).
