# Project Technical Overview

## 기술 방향

`agent-factory`는 Python 중심의 실행 코어 위에 에이전트 정의, 스킬 로딩, 정책, 문서 계약, 워크플로, 메모리, 검색 계층을 얹는 구조를 지향한다.

## 핵심 기술 요소

- Python 기반 실행 코어
- YAML 기반 에이전트, 정책, 설정 정의
- Markdown 기반 문서와 작업 기록
- CLI provider 및 내부 runtime 공존
- 훅 기반 실행 제어와 문서 계약
- 프로젝트 단위 데이터, 메모리, 런 기록 저장

## 주요 서브시스템

- `core/`: 실행기, 오케스트레이션, 훅, 메모리, 라우팅
- `skills/`: 스킬 구현과 레지스트리
- `agents/`: 에이전트 정의
- `projects/`: 프로젝트별 상태, 런, 데이터
- `docs/`: 설계, 운영, 작업 문서
- `tests/`: 단위 테스트, 통합 테스트, 회귀 테스트

## 기술 제약

- 기존 자동화가 기대하는 파일명과 경로를 함부로 제거하지 않는다.
- 호환성이 중요한 공개 함수와 도구 인터페이스는 점진적으로 바꾼다.
- 설계 변경은 문서와 함께 반영되어야 한다.
- 테스트가 불가능한 변경은 최소한 수동 검증 계획이 있어야 한다.

## 설계 원칙

- 한 번에 전부 바꾸지 않고 adapter, facade, hook 같은 경계면부터 정리한다.
- 새 구조는 기존 구조를 흡수하되, 레거시 참조를 즉시 끊지 않는다.
- 실행 전 문서 승인, 실행 후 검증 기록을 남긴다.

## 문서 운영 원칙

- 기술 스택, 런타임 제약, 상위 설계 원칙이 바뀌면 이 문서를 갱신한다.
- 작업별 설계 문서는 이 문서와 충돌할 수 없다.
