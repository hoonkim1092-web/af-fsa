# [Agent Factory] 비개발자용 Auto-Harness 파이프라인 명세서 (v2.0)

## 1. 개요 (Overview)
본 명세서는 `agent-factory` 내에서 코딩 지식이 없는 비개발자가 텍스트 지시만으로 고품질의 에이전트를 자동 생성, 조립, 배포할 수 있도록 하는 **전자동 하니스(Auto-Harness) 파이프라인**의 상세 설계를 다룹니다.

## 2. 핵심 설계 철학 (Core Philosophy)
1.  **비개발자 친화성 (No-Code UX):** 복잡한 프롬프트 엔지니어링 템플릿을 사용자에게 강제하지 않고, 최소한의 정보 입력만으로 시스템이 스펙 문서를 자동 빌드업합니다.
2.  **'고스트-파일럿 (Ghost-Pilot)' 완전 자동화:** "사용자는 아무것도 몰라도 알아서 다 해줘야 한다"는 철학입니다. CLI에서 `고스트-파일럿`을 선언하면, AI가 병렬로 다중 에이전트를 가동하여 구조 분석부터 코드 시뮬레이션 작성, 자체 검증까지 사용자 개입 없이 100% 완료하는 자율 실행 모드를 제공합니다.
3.  **에이전트 하네스 (다중 모델 협업):** 특정 벤더의 AI 모델에 종속되지 않고, 작업별 특성(속도, 정밀도, 추론력)에 가장 부합하는 최적의 뇌(엔진)를 동적으로 할당하여 씌우는 *'말 장구(Harness)'* 역할을 수행합니다. 모든 모델 선택은 **동적 티어(Dynamic Tier 1/2/3)** 시스템을 따릅니다. 이를 통해 각 에이전트들이 고유의 강점을 살려 **병렬(Parallel)**로 작업을 수행합니다.
4.  **Zero-Fat 아키텍처 (Lightweight Control):** 무거운 DB나 복잡한 룰 엔진 의존도를 낮추고, 텍스트 기반 감사 로그, 스냅샷 백업, 단일 설정 파일(Policy)을 통해 무결성과 보안을 최대한 통제합니다.

## 3. 5단계 코어 워크플로우 (Core Workflow)
비개발자 사용자가 직관적으로 이해하고 경험하게 될 5단계의 거시적 흐름입니다.

1. **지시 흡수 (Context Absorption):** 사용자가 대화창이나 문서로 요구사항을 입력하면, 팩토리 시스템이 필요한 페르소나와 도구를 파악합니다.
2. **가이드 템플릿 (Guided Template):** 파악된 초안을 바탕으로 직관적인 입력 폼과 리스크 등급을 띄워 사용자에게 확인받습니다. (※ `고스트-파일럿` 모드 시 본 단계 생략)
3. **다중 모델 자동 하네스 (Multi-Model Agent Harness):** 사용자가 빈칸으로 넘긴 설정(AI 배정)을 시스템이 스킬 특성에 맞춰 동적으로 주입합니다. 빠른 관찰은 **Tier 1 (속도 특화)**, 고도의 코딩 조작은 **Tier 2 (정밀 특화)**, 복잡도 높은 기획 및 쿼리는 **Tier 3 (추론 특화)** 엔진을 설정 파일(`config.yaml`)에서 불러와 자동 할당합니다.
4. **리스크 통제 (Risk Policy Gate):** 외부로 데이터를 보내거나 시스템을 조작하는 등 치명적인 권한이 감지되면 시스템이 멈추고 결재를 대기합니다. (※ 단, `고스트-파일럿` 모드일지라도 치명적 시스템 조작 전에는 반드시 멈춤)
5. **조립 및 병렬 워크 가동 (Assemble & Parallel Run):** 에이전트 명부를 백업해두고, 각기 다른 특화 뇌를 탑재한 다수의 에이전트가 완벽히 조립되어 **동시에 병렬로** 작업을 전개(Deploy)합니다.

## 4. 코어 상세 파이프라인 (Detailed Core Pipeline)
오케스트레이터(Orchestrator)와 내부 시스템이 백그라운드에서 처리하는 기술적 데이터 파이프라인입니다.

### [STEP 1] 컨텍스트 흡수 (Context Absorption)
*   **Trigger:** 사용자 CLI 입력, 웹 폼, 또는 `Master_Spec.md` 업로드 이벤트. 
*   **Process:** 
    1.  오케스트레이터 LLM이 입력된 텍스트의 문맥을 파싱(Parsing)합니다.
    2.  목표 달성에 필요한 **다중 에이전트 트리(역할)**와 **스킬 목록(Tools)**을 JSON 객체로 도출합니다.
*   **Output:** `draft_agent_spec.json` (임시 적재 설계도)

### [STEP 2] 친절한 템플릿 생성 & 가이드 (Guided Template)
*   **Trigger:** STEP 1에서 `draft_agent_spec`이 생성된 직후 호출.
*   **Process:**
    1.  비개발자 사용자가 컴펌할 수 있는 대화형/시각적 위저드(Wizard) 화면을 노출합니다.
    2.  `[리스크 마킹]` 기능: 도출된 스킬 이름 옆에 단일 정책 엔진(`policy.yaml`)의 위험 등급을 텍스트/컬러 태그로 시각화합니다. (예: `웹 검색[LOW]`, `터미널 실행[CRITICAL]`)
    3.  페르소나, 목표 등의 빈칸 폼에 시스템 추천값(Placeholder)을 기본 삽입합니다.

### [STEP 3] 빈칸 채움 & 다중 모델 에이전트 하네스 (Multi-Model Auto-Harness)
*   **Trigger:** 사용자 템플릿에서 'Apply(적용)' 이벤트 발생 시. (또는 `고스트-파일럿` 선언 시 즉시 패스루)
*   **Process:** 
    1.  **Default 덮어쓰기:** 비워둔 텍스트 항목을 프로젝트 헌법(`GEMINI.md`) 기반 Zero-Integration 원칙 보안 문구로 덮어씌웁니다.
    2.  **[핵심] 스킬 특성 분석 및 '카테고리 기반 동적 티어 할당' 로직:** 스킬 셋의 본질적 요구사항(형태소 및 카테고리)을 분석하여, 가장 특화된 성향의 프론티어 AI 모델을 동적으로 주입합니다. 벤더명을 하드코딩하지 않고 환경설정 파일(`config.yaml`)에 매핑된 최신 Tier 모델을 끌어옵니다.
        *   🔵 **Tier 1 (초고속/대량관찰):** 수십 개 파일의 동시 읽기, 데이터 요약, 단순 정보 취합 위주.
        *   🟣 **Tier 2 (정밀 구현/코드):** 복잡하고 미묘한 뉘앙스, UI/UX 디자인 검토, 복잡도 높은 코드 작성 위주.
        *   🟢 **Tier 3 (논리 추론/매니지먼트):** 다중 에이전트 조율, 전략 및 스케줄 산출, 고도의 리서치 쿼리 기획 위주.
    3.  **LLMEngine Auto-Upgrade 스캐너:** 사용자가 특정 과거 벤더 모델(예: `gemini-1.5-flash`)을 지정하거나 템플릿에 남아있더라도, 내부 엔진이 `genai.list_models()` API를 통해 현재 활성화된 가장 최신 프론티어 플래시 모델(예: `gemini-3.0-flash`)을 스캔하여 알아서 버전을 격상(Auto-Upgrade) 배정합니다. (단, 사용자가 명시한 버전이 API 탐지 버전보다 높을 시 다운그레이드를 방지합니다.)

### [STEP 4] 🛡️ 3단 리스크 정책 엔진 검문소 (Deny-by-default)
*   **Trigger:** 스펙 조립(STEP 3) 완료 직후.
*   **Process:** 에이전트 스펙이 `policy.yaml` (단일 정책 엔진) 룰을 통과하는지 검증 후, **가장 높은 리스크 등급(Max Risk)** 기준으로 분기합니다.
    1.  **Low / Medium (안전):** 
        *   팝업 없이 즉시 조립 단계로 패스.
    2.  **High (사후 감사 대상):** 
        *   중단 없이 자동 패스하되, 백그라운드에서 Immutable Audit Log 시스템(`.system_generated/logs/audit.log`)에 이벤트를 자동 기록합니다.
    3.  **Critical (사전 블로킹 및 보스 결재):** 
        *   시스템 가동을 즉시 정지하고 붉은색 경고 출력 (예: "⚠️ 치명적 스킬이 포함되었습니다. 강제 생성하시겠습니까? Y/N").
        *   'Y' 입력 시에만 패스되며, **해당 승인 이력은 고도의 불변성을 지닌 감사 로그에 강제 박제**됩니다.
        *   **(기술적 불변성 검증 기준):** 로그는 반드시 포맷된 해시 체인을 동반해야 합니다.
            *   *포맷: `[TIMESTAMP] | [PREV_HASH] | [ACTION: USER_XX CREATED AGENT_YY WITH SKILL_ZZ] | [CURRENT_SHA256_HASH]`*

### [STEP 5] ⏪ 버전 스냅샷 백업 & 조립 완료 (Snapshot & Assemble)
*   **Trigger:** STEP 4 정책 검문소를 완전히 통과한 시점.
*   **Process:** 
    1.  **안전망 (Versioned Rollback):** 최종 `registry.yaml` 쓰기(Write) 직전, 원본 파일을 타임스탬프와 함께 백업 폴더로 복사(`registry_YYYYMMDD_HHMMSS.yaml`)하여 사고 시 원상 복구(Rollback) 환경을 보장합니다.
    2.  **스킬 로딩 및 재활용 통제:** 기존 로직을 탐색하여 이미 존재하는 스킬 모듈은 코드 생성 없이 재활용(Binding)합니다.
    3.  **최종 조립 데이터베이스 등재:** 조립 완료된 스펙 JSON이 최신 `registry.yaml`에 등재되며 생성이 완료됩니다.

## 5. 단계별 검증 기준 (Definition of Done - DoD)
본 파이프라인의 설계가 정상적으로 구현되었음을 판단하기 위한 구체적인 테스트 조건입니다.

1.  **[STEP 1~3 검증] 라우팅 및 가이드 정상 동작**
    *   `agent_launcher.py` (또는 오케스트레이터 CLI) 로드 시, 대화식 Wizard가 에러 없이 시동되어야 함.
    *   "단순 로그 요약 에이전트" 요청 시 특정 벤더명이 고정할당되지 않고, 시스템이 `Tier 1 (속도 특화)` 라우팅 판정을 내려 동적으로 할당됨을 터미널 출력(Dry-run)에서 확인할 수 있어야 함.
2.  **[STEP 4 검증] 정책 엔진 블로킹 및 Immutable 로깅 (명확한 기술 검증)**
    *   `HIGH` 또는 `CRITICAL` 승인 발생 시, `.system_generated/logs/audit.log` 에 신규 로그가 강제 Append 되어야 함.
    *   **검증 스크립트 통과 요건:** 관리자가 파이썬 해시 검증 스크립트(예: `python verify_audit_hash.py`)를 실행했을 때, 로그 내 모든 라인의 연쇄 `[PREV_HASH]` 와 `[CURRENT_SHA256_HASH]` 체인이 수학적으로 일치하고 무결성 변조가 0% 임을 stdout으로 반환해야 함.
3.  **[STEP 5 검증] 스냅샷 및 파일 갱신**
    *   에이전트 조립 완료 이벤트 직전, `backup_registry/` 디렉토리 하위에 정상적인 타임스탬프 형식의 `.yaml` 스냅샷 파일이 생성됨을 확인해야 함 (PASS 조건).

## 부록 A. 모듈 매핑 및 개발 범위 (Codebase Mapping)
*   **CLI 입출력 / 오케스트레이션 (`project_orchestrator.py`):** STEP 1, STEP 2, STEP 4 담당 로직 및 사용자 인터페이스 연동.
*   **생성 조립 및 자원 라우팅 (`factory_manager.py`):** STEP 3, STEP 5 담당 코어 로직 수행.
*   **정책 엔진 스키마 (`policy.yaml`):** 스킬별 권한(LOW~CRITICAL) 등급 및 티어(Tier) 정의. (신규 구성 파일)
*   **재활용 스토리지 (`registry.yaml`):** 최종 산출물(에이전트 군단)이 관리되는 핵심 Database.
*   **보안 스토리지 파이프라인:** 
    *   `.system_generated/logs/audit.log` (단순 append가 아닌 해시 체인 또는 OS 권한 잠금을 이용한 Immutable Log 환경)
    *   `backup_registry/` (자동 버전명 기반 స్냅샷 디렉토리)
