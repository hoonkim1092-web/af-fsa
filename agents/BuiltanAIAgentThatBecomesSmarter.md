I Built an AI Agent That Becomes Smarter Every Day (n8n)")에 따르면, n8n과 벡터 데이터베이스(Vector Database)를 활용해 AI를 학습시키는 원리는 모델 자체를 재학습(Fine-tuning)시키는 것이 아니라, '동적 퓨샷 러닝(Dynamic Few-Shot Learning)' 혹은 RAG(검색 증강 생성) 방식을 통해 AI에게 최적의 예시를 제공하는 것입니다.
이 시스템의 핵심 원리와 구현 과정은 다음과 같습니다.
1. 핵심 원리: 관련성 높은 예시만 골라내기
일반적으로 AI 에이전트에게 업무를 지시할 때 예시(Few-shot)를 제공하면 성능이 좋아집니다. 하지만 프롬프트에 넣을 수 있는 예시의 수에는 한계가 있으며(보통 5~20개), 너무 많은 예시는 오히려 AI를 혼란스럽게 하거나 토큰 비용을 높입니다.
이 시스템은 벡터 데이터베이스를 활용하여, 사용자의 현재 요청과 의미적으로 가장 유사한(Semantic Search) 예시 4~6개만을 데이터베이스에서 찾아내어 프롬프트에 동적으로 주입합니다,. 이를 통해 AI는 현재 상황에 딱 맞는 '참고서'를 보며 답변하게 되므로 정답률이 비약적으로 상승합니다(영상에서는 67%에서 95%로 상승).
2. 구현 단계 및 작동 프로세스
이 학습 메커니즘은 크게 데이터 동기화(저장) 과정과 AI 에이전트 실행(검색 및 생성) 과정으로 나뉩니다.
A. 데이터 동기화 (예시 학습시키기)
1. 예시 데이터베이스 구축: 구글 시트나 n8n 데이터 테이블에 요구사항(Input), 추천 답변(Output), 설명(Explanation) 컬럼을 가진 테이블을 만듭니다. 특히 '설명' 부분은 AI가 왜 이 답변이 정답인지 문맥을 이해하는 데 중요합니다.
2. 임베딩(Vectorization): n8n 워크플로우를 통해 새로운 예시가 추가되면, OpenAI의 임베딩 모델(예: text-embedding-3-small)을 사용하여 이 텍스트 데이터를 숫자로 된 벡터 값으로 변환합니다.
3. 벡터 DB 저장: 변환된 벡터와 원본 메타데이터(ID, 요구사항, 답변, 설명 등)를 Supabase와 같은 벡터 데이터베이스에 저장합니다,.
B. AI 에이전트 실행 (지식 활용하기)
1. 유사성 검색: 사용자가 새로운 질문(요구사항)을 입력하면, n8n은 이를 다시 벡터로 변환한 뒤 벡터 데이터베이스에서 가장 '의미가 비슷한' 예시들을 검색합니다. 키워드가 일치하지 않아도 문맥적 의미가 통하면 찾아냅니다.
2. 프롬프트 주입: 검색된 상위 예시들(예: 상위 4개)을 JSON 형식 등으로 포맷팅하여 AI 에이전트의 시스템 프롬프트에 "참고 예시"로 포함시킵니다,.
3. 답변 생성: AI는 제공된 유사 사례를 바탕으로 새로운 질문에 대한 최적의 답변을 생성합니다.
3. 지속적인 학습(Feedback Loop)
이 시스템이 "매일 더 똑똑해지는" 이유는 피드백 루프 때문입니다. 만약 AI가 잘못된 답변을 내놓거나 새로운 유형의 질문을 처리하지 못할 경우, 사용자는 올바른 답변과 그 이유가 담긴 새로운 예시를 데이터 테이블에 추가하기만 하면 됩니다.
그러면 n8n이 자동으로 이를 벡터 DB에 업데이트하고, 다음부터 AI는 유사한 질문이 들어왔을 때 이 새로운 예시를 참조하여 올바르게 답변하게 됩니다. 즉, 코드를 수정할 필요 없이 데이터만 추가함으로써 AI의 성능을 지속적으로 개선할 수 있습니다.
n8n에서 Supabase 벡터 데이터베이스(Vector DB)를 연동하여 AI 학습 시스템(RAG)을 구축하는 과정은 크게 Supabase 설정, n8n 연결, 그리고 데이터 저장 및 검색의 3단계로 나뉩니다.
구체적인 단계별 방법은 다음과 같습니다.
1. Supabase 프로젝트 설정 (사전 준비)
n8n과 연동하기 전에 Supabase 콘솔에서 벡터 저장을 위한 환경을 구성해야 합니다.
• SQL 스크립트 실행: Supabase의 SQL Editor에서 벡터 저장소(Vector Store)를 생성하는 스크립트를 실행해야 합니다. 이때 가장 중요한 점은 벡터 차원(Dimension)을 1536으로 설정하는 것입니다. 이는 추후 사용할 OpenAI 임베딩 모델(text-embedding-3-small)의 차원과 일치해야 하기 때문입니다.
• RLS 설정: 테이블이 생성된 후, 외부(n8n)에서 데이터를 읽고 쓸 수 있도록 RLS(Row Level Security)를 비활성화하거나 적절한 정책을 설정해야 합니다.
• API 정보 확보: Project Settings > Data API 메뉴에서 **Project URL(Host)**을 복사하고, API Keys 메뉴에서 Service Role Secret (service_role) 키를 복사해 둡니다.
2. n8n에서 Supabase 연결 (Credential)
n8n의 Supabase 노드에서 자격 증명을 생성합니다.
• Host: 앞서 복사한 Project URL을 입력합니다.
• Service Role Secret: 복사해 둔 Secret Key를 입력하고 저장하면 연결이 완료됩니다.
3. 데이터 저장 (Embedding & Upsert)
새로운 예시(데이터)를 벡터화하여 Supabase에 저장하는 과정입니다. Supabase Vector Store 노드를 사용합니다.
• 노드 설정: Supabase Vector Store 노드를 추가하고, Operation을 Insert Documents로 설정합니다.
• 임베딩 모델 연결: 이 노드의 'Embeddings' 입력 포트에 OpenAI Embeddings 노드를 연결합니다. 모델은 반드시 text-embedding-3-small을 선택하여 Supabase 설정(1536 차원)과 일치시킵니다.
• 데이터 매핑:
    ◦ Data Mode: JSON 데이터 처리를 위해 Load specific data를 선택합니다.
    ◦ 텍스트(Document): 임베딩할 실제 텍스트(예: 사용자의 요구사항)를 지정합니다.
    ◦ 메타데이터(Metadata): 검색 후 AI에게 문맥을 제공하기 위해 필요한 정보들(ID, 요구사항, 추천 답변, 설명 등)을 모두 메타데이터 필드에 매핑하여 함께 저장해야 합니다.
4. 데이터 검색 (Retrieval)
AI 에이전트가 질문을 받았을 때 관련 예시를 찾아오는 과정입니다.
• 노드 설정: Supabase Vector Store 노드를 사용하되, 이번에는 검색을 위해 설정합니다. (자료에서는 Get Rank Documents 또는 Get Many Operation을 사용하며, 쿼리 설정을 통해 유사도 검색을 수행합니다).
• 프롬프트 입력: 사용자의 현재 질문(Input)을 프롬프트 항목에 연결합니다. 이 텍스트가 벡터로 변환되어 DB 내의 데이터와 비교됩니다.
• 옵션 설정:
    ◦ Limit: AI에게 너무 많은 정보를 주지 않기 위해 상위 4개(Limit: 4) 정도만 가져오도록 설정합니다.
    ◦ Metadata 포함: 저장된 답변과 설명(Explanation)을 AI가 읽어야 하므로 메타데이터를 포함해서 가져오도록 설정합니다.
이 과정을 통해 n8n은 사용자의 질문이 들어올 때마다 Supabase에서 가장 유사한 예시를 검색(Retrieve)하고, 이를 프롬프트에 포함시켜 AI에게 전달하게 됩니다.

1. 사례 개요
• 목표: 사용자의 업무 스타일과 요구사항을 입력받아 가장 적합한 생산성 도구(Notion, Jira, Google Workspace 등 8개 옵션 중 하나)를 추천.
• 성과: 초기 성공률 67% → 벡터 DB 도입 후 **95%**로 상승.
• 사용 도구: n8n (워크플로우 자동화), Supabase (벡터 데이터베이스), OpenAI (임베딩 및 LLM).
2. 기존 방식의 문제점 (Before)
초기에는 시스템 프롬프트에 8개 도구에 대한 설명과 일반적인 지침만 포함되어 있었습니다.
• 맥락 부족: AI는 도구의 기능은 알지만, 사용자의 미묘한 상황(예: "가벼운 툴 선호", "직접 설정 가능 여부")에 따라 언제 무엇을 선택해야 하는지 판단하는 '컨텍스트'가 부족했습니다.
• 예시의 한계: 프롬프트에 고정된 예시를 많이 넣으면(20개 이상), AI가 혼란스러워하거나 토큰 비용이 증가하여 성능이 오히려 떨어지는 문제가 있었습니다.
3. 해결된 시스템 구조 (After)
이 문제를 해결하기 위해 '동적 예시 주입(Dynamic Example Injection)' 방식을 도입했습니다.
A. 데이터베이스 구축 (학습 데이터)
먼저 Examples라는 데이터 테이블을 만들어 다음 3가지 컬럼을 관리합니다.
1. Requirements (요구사항): 사용자가 입력할 법한 상황 묘사.
2. Recommendation (추천 도구): 그 상황에서의 정답 도구.
3. Explanation (이유): 왜 이 도구가 정답인지에 대한 논리적 설명. (이 부분이 AI 학습의 핵심입니다.)
B. 작동 프로세스 (Workflow)
사용자가 질문을 던지면 n8n은 다음과 같은 4단계 과정을 거칩니다.
1. 입력 및 벡터화: 사용자의 요구사항(Input)을 받아 OpenAI 임베딩 모델(text-embedding-3-small)을 통해 벡터 값으로 변환합니다.
2. 유사성 검색 (Vector Search): Supabase 벡터 DB에서 사용자의 질문과 의미적으로 가장 유사한 과거의 성공 사례를 검색합니다. 키워드가 달라도 문맥(Meaning)이 비슷하면 찾아냅니다.
3. 상위 예시 추출: 가장 관련성이 높은 **상위 4개(Limit: 4)**의 예시만 추출합니다. 4개 정도가 AI에게 가장 효과적인 맥락을 제공하기 때문입니다.
4. 프롬프트 주입: 추출된 4개의 예시(상황+정답+이유)를 JSON 형식으로 포맷팅하여 AI의 프롬프트에 동적으로 포함시킵니다.
4. 실제 적용 예시 (성공 사례)
영상에서 소개된 구체적인 시나리오는 다음과 같습니다.
• 사용자 입력: "나는 주로 구글 캘린더와 지메일에서 살다시피 하고, 무거운 도구를 추가하지 않고 가볍게 할 일을 관리하고 싶어."
• 벡터 DB 검색 결과: 시스템은 과거 데이터 중 이와 유사한 패턴을 찾아냅니다.
    ◦ 저장된 유사 사례: "Google 생태계 중심의 가벼운 관리" → 추천: "Google Workspace" → 이유: "이미 구글 환경에 익숙하므로 새로운 툴 학습 없이 가장 효율적임."
• AI의 최종 답변: 검색된 사례의 논리를 참고하여, 복잡한 Notion이나 Jira 대신 Google Workspace를 추천하고 그 이유를 정확히 설명합니다.
5. 지속적 학습 (Learning Mechanism)
이 시스템이 "매일 똑똑해지는" 이유는 피드백 루프 때문입니다.
• 만약 AI가 틀린 답을 내놓으면, 사용자는 코드를 수정하는 대신 데이터 테이블에 올바른 예시 하나를 추가하기만 하면 됩니다.
• n8n 스케줄러가 매일 밤 새로 추가된 예시를 벡터 DB에 자동 동기화(Upsert)합니다.
• 다음 날부터 AI는 유사한 질문이 들어올 때 이 새로운 예시를 참고하여 정답을 맞히게 됩니다.
결과적으로 이 방식은 AI 모델 자체를 재학습(Fine-tuning)시키는 비용 없이, 데이터(예시) 관리만으로 AI의 지능과 정확도를 지속적으로 향상시키는 매우 효율적인 방법입니다.
