# 코드 리뷰 가이드

> 이 문서는 사용자가 자유롭게 편집할 수 있는 Knowledge 스킬입니다.
> 에이전트는 관련 작업 시 이 절차를 자동으로 참고합니다.

## 1. 변경 사항 파악

- [ ] PR의 목적과 범위를 이해합니다
- [ ] 변경된 파일 목록을 확인합니다
- [ ] 커밋 메시지가 변경 내용을 정확히 설명하는지 확인합니다

## 2. 보안 점검

- [ ] 하드코딩된 API 키, 비밀번호, 토큰이 없는지 확인합니다
- [ ] SQL 인젝션, XSS 등 입력 검증 취약점을 점검합니다
- [ ] 민감한 데이터가 로그에 노출되지 않는지 확인합니다

## 3. 성능 점검

- [ ] N+1 쿼리 패턴이 없는지 확인합니다
- [ ] 불필요한 반복문이나 중복 연산을 점검합니다
- [ ] 대용량 데이터 처리 시 페이지네이션이 적용되었는지 확인합니다

## 4. 코드 품질

- [ ] 함수/클래스의 단일 책임 원칙(SRP)이 지켜지는지 확인합니다
- [ ] 에러 핸들링이 적절한지 점검합니다
- [ ] 테스트 코드가 변경 사항을 충분히 커버하는지 확인합니다

## 5. 리뷰 완료

- 승인 시: "LGTM 🎉" 코멘트와 함께 Approve
- 수정 요청 시: 구체적인 개선 사항을 코드 라인에 직접 코멘트
